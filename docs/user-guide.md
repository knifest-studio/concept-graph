# User guide

Install the app using the [setup guide](setup.md).

On cloud team boards, **Chat** opens a non-modal panel. Enter sends; Shift+Enter adds a line. **Load earlier** pages through the newest 5,000 messages. Authors can delete their messages; the board owner can delete any. Select a node, then **Attach selected node** to add a link that switches page, selects and highlights it. A removed node's link is disabled. The unread badge remembers your place per board and account on this device; a quiet alert plays when chat is closed or the tab is hidden, subject to **Sounds** and browser audio permission. Viewers can chat too. Connected cloud MCP agents can read and post, marked **via agent**.

**Voice → Join voice** requests microphone access and joins an audio-only call for up to eight participants. **Mute microphone** silences your track; **Leave voice** releases the mic. Speaking/muted marks appear on participant avatars before you join. If the browser blocks remote audio, choose **Play voice audio**. Leaving the board leaves voice. A short board-connection drop keeps the microphone and peer connections for up to 20 seconds and automatically requests admission again after reconnect. Failed admission or a longer drop leaves voice and releases the microphone. Voice is peer-to-peer (participants may see each other's IP address), may use Cloudflare TURN, and is not recorded. Both features are cloud-only. See [cloud configuration](cloud-preview.md#text-and-voice-chat).

The desktop preview and source-run browser app share the canvas controls below. The desktop preview includes Node.js, uses an existing or separately downloaded Codex CLI, and runs in a native window; see [desktop preview setup](desktop-preview.md) for platform support and current limitations.

## Use

- Click **+ Add text prompt** in the sidebar, the empty canvas button, or press **T**. New prompts are selected and focused, and brought into view when needed. Add references using upload, drag-and-drop, or **⌘V**.
- Paste plain text on the canvas to make a text node. Pasting while editing a prompt works normally.
- Drag a node's right connection dot to the left dot of a prompt.
- Every generation uses **GPT-6-Luna** with **low** reasoning effort. Older boards and exports retain saved model/effort fields for compatibility; these fields do not affect generation. This selects the Codex agent, not necessarily the image generator, and does not change your global Codex settings.
- Describe the image you want, then click **Generate** or press **⌘Enter** on Mac / **Ctrl+Enter** elsewhere. Empty prompts need text or saved custom instructions. The **Inputs** chip counts directly connected image and text nodes; those nodes and their template references are sent with the request. Disconnected branches and indirect ancestors are excluded.
- Request several separate images in your prompt. Each returned image becomes its own node. Runs queue one at a time.
- Every expanded image shows its editable name above it. Click the name to edit it, then refer to connected images by those exact names, for example **take the clouds from “Storm 3” and the angle from “Canyon”**. The same names are sent to Codex, Nano Banana and describe runs, together with each image’s node ID (**Copy node ID** in the right-click menu) and file name, so a prompt may use any of the three. Fullscreen view shows the file name a download gets, the original name of an uploaded file, and the node ID, each with a copy button. Uploads use the file name without its extension. Generated images use the model’s caption when available, otherwise the next free **Image N**. New names are unique across all pages, and upscales use **`<source name> upscaled`**. Copies retain their names. Older unnamed images show a file-derived name or **Image** and receive a stored unique name when connected to a prompt. Automatic names describe the requested result and may be inaccurate.
- Use the type selector in a text node's header to apply a saved custom node or switch back to **Text prompt**. A plain prompt's selector appears on hover, selection or keyboard focus; custom nodes always show it. The written text, position and connections stay in place. Switching back removes the custom instructions and fixed references from that node.
- On team boards, the arrow beside **Generate** chooses who generates that prompt: your own **Codex** (the default) or **Nano Banana**, which runs on the site's Gemini key without the helper when the site owner has set it up and added you to its allowed list. Nano Banana prompts show a yellow **Nano Banana** button. The menu's last line shows how many images you have left today and the team's spend this month, or why Nano Banana is unavailable; limits reset daily (per person, UTC) and monthly (team budget). Its images arrive on the board like Codex results.
- While running, the header shows **Generating… 12s** and a separate **Cancel** control for your run. In cloud mode, another artist's run shows their name. History shows returned image counts. Codex does not expose a live completion percentage or ETA.
- In cloud/hosted mode, the top bar distinguishes a disconnected helper, Codex sign-in and readiness. A selected blocked prompt has an action to connect or sign in. **Connect and generate** resumes only if its text, template and directly connected inputs still match the original click; otherwise review it and click Generate again. Cancelling setup, switching boards or navigating away cancels that pending request.
- The **Getting started** card records this viewer's own prompt, generation and variation actions in browser storage. It is never part of a board. Dismiss it with **×**, or reopen it and five short canvas tips with **?** in the top bar.
- Hover, select or keyboard-focus an image and choose **+ Prompt from this** to make a connected variation prompt in free space to its right. Existing nodes stay in place, and the new prompt receives focus.
- Open **History** and select a run's diagnostics to inspect the available agent messages, model and effort, events, errors and token usage. Availability depends on what Codex reports; older runs may have no diagnostics. Diagnostics are stored locally with the run and included in board exports, so review their contents before sharing.
- Token usage is cumulative across agent model calls: cached input is part of Input and reasoning is part of Output. Similar totals on different models do not establish equal subscription usage. Image-generation usage may not be included. Initial thread settings are recorded before any per-generation overrides.
- Drag an image or text node's output dot into empty canvas space to create a connected text prompt. Its text cursor focuses automatically so you can type immediately.
- Images keep their original proportions. Hover to darken the image and reveal its fullscreen button, which stays 44 screen pixels across but never grows past a third of the image when you zoom far out.
- Fullscreen shows the original image to inspect closely: scroll or pinch to zoom where the pointer is, drag to move around, double-click to switch between the whole image and its real pixels, or use the bar at the bottom (−, the zoom level, +, **Fit**, **1:1**). Keys: **+** and **−** zoom, **0** fits, **1** shows real pixels, the arrows move. Past 300% pixels are drawn square, so detail is not blurred.
- Images 2K or larger (on the long side) show a size badge in their corner (2K, 3K, 4K, 6K, 8K) that stays readable when zoomed out; hover it for the exact pixels. Uploads record their size; on team boards, images added before this learn theirs when the board next opens.
- Create, switch, or rename boards in the sidebar (on team boards, only a board's owner can rename it). Each board has its own nodes, connections, viewport, and run history; pending edits save before switching. Generation continues on its original board when you switch away.
- On team boards, a new board is private: only you and the people you invite can open it. Choose **Share** in the board's top bar to invite people by email as **Can edit** or **Can view**, change or remove them, and set **General access** to **Only invited people**, **Anyone with the link** or **Everyone who signs in**, with view or edit for the link. No email is sent: use **Copy link** and send it yourself; an invited person sees the board after signing in with that address, and a board opened from its link stays in their list. People who are not the owner see who has access and their own role. The boards home lists **Your boards** and **Shared with you**, each tile showing its access and, on shared boards, your role. Someone without access who opens the link sees **You don't have access to this board** with the owner's name. A board's address (`/b/…`) opens it directly, also after signing in, and Back returns to the boards home.
- With **Can view** you see the board, its changes and cursors live, and can select, copy, zoom, pan, switch pages, open images fullscreen and see custom nodes, but nothing can be changed; the top bar shows **View only**. If the owner changes your role while you are on the board, it reloads with the new role.
- Use **CUSTOM NODES** to save a reusable text-node template with additional instructions and up to 10 reference images. Add a template to a board and write any task-specific text in the new node. Each inserted node keeps its own settings and references if the library template is later edited or deleted. The 10-image limit applies to all reference images in a run, including those from custom nodes.
- Right-click a text node and choose **Save as custom node** to start a template from its prompt, saved instructions and directly connected reference images. Saving the template keeps the original node intact. On team boards custom nodes belong to the board: everyone who can open it sees and uses them, people who can edit it can change them, and changes reach everyone on the board at once (the last edit wins). A board made before custom nodes belonged to boards starts with a copy of the old team library.
- Each custom type has a palette colour on its badge, border, header and collapsed square. New templates start with the least-used colour; choose a swatch in the template dialog to change it. Existing board nodes retain their saved colour when the library changes.
- Split a board into pages under **Pages** in the sidebar, like Figma: **+** adds a page, double-click a page (or press F2) to rename it, and right-click it to rename or delete it. Deleting a page also deletes its nodes; **Undo** restores them, and a page cannot be deleted while it has an active generation or if it is the last page. Each page has its own nodes, connections and groups; new, pasted and duplicated nodes go to the open page, and generated images go to the page of their prompt. Selection, alignment, fitting the view, copying and the node count work on the open page; history and limits stay board-wide. The app remembers your open page and each page's view on this device. On team boards, avatars in the page list show who is on each page, and cursors show only for people on your page.
- Change what is in front, like Figma: right-click a node, sticky, stamp or drawing and choose **Bring to front** (`]`), **Bring forward** (`⌘ ]` / `Ctrl+]`), **Send backward** (`⌘ [` / `Ctrl+[`) or **Send to back** (`[`). The shortcuts act on the selected nodes of the open page; a menu command on an unselected node moves only that node. New, pasted, duplicated and generated nodes appear in front. A stamp attached to a node is always drawn above it and moves with it in the layer order. Layer order is undoable and syncs on team boards; group frames stay behind their members, and sections behind everything.
- Large boards stay responsive: only cards near the screen are drawn, and below about 40% zoom cards switch to a lighter view with small image previews and no image captions (a card you are editing stays complete). On a page with more than 1,500 nodes, fitting the view stops at 15% zoom; far out on a crowded page, images not yet loaded show a placeholder. On team boards the first person to view an image stores a small preview, so teammates zooming out download previews instead of originals; fullscreen and **Download original** always use the original.
- Switch light/dark themes with the sun/moon button. Text connections are blue; image connections are purple.
- Pan with the trackpad or middle/right drag; passing over prompts keeps panning. Click a prompt to edit it. Prompt cards grow and shrink to fit their text, without internal scrolling. Pinch to zoom; use the bottom toolbar to fit selected nodes, or the whole canvas when nothing is selected. Drag on the canvas, including inside a section, to select everything the box touches, as in FigJam; arrows and drawings count where their line runs, and the section you start in is not picked. **Shift**-click (or **⌘**-click) adds or removes one item, and a **Shift**-drag flips what the box touches: unselected items join the selection and selected ones leave it. Two or more selected items share one box with corner handles, however they were selected; drag any selected item or the box's empty inside to move them all, and click that empty inside to clear the selection. A click on one item of a selection selects just that item.
- Groups bundle nodes and fold them into one compact card. Images from the same generation are grouped automatically as they arrive, starting with the second ungrouped image; partial results remain after cancellation or an error. Select at least two ungrouped nodes with a selection rectangle or **⌘-click**, then press **Group selected nodes** in the bottom toolbar. The group's small name, node count and controls sit in its frame's header: double-click the name to rename it, use the chevron to fold/unfold the group, and drag the header to move the members together. **Ungroup** removes only the frame, keeping all nodes; selecting a group and pressing Delete also ungroups it. Groups persist on their board and do not change generation inputs or connections. Groups support one level, without nesting. Group colours from earlier versions stay in the board but are no longer shown; use a section for a coloured background.
- Sections work like FigJam sections: a named, coloured background frame that holds whatever you place in it. Choose **Section** in the bottom toolbar (or press **Shift S**) and drag on the canvas to draw one; a click makes a default-size section. With nodes selected, **Shift S** or **Wrap in section** in the right-click menu frames them in a new section. A node, sticky, stamp or drawing belongs to the section its centre is in; a group goes with a section when its frame's centre is inside, a stamp goes with the node it is attached to, and a smaller section inside a larger one goes with it. Drop things into a section or drag them out to change what it holds. Drag a section by its title or edge to move it with everything inside; what it passes over during the drag stays put. A drag in its empty inside selects or pans as usual. A selected section shows resize handles; resizing never moves its contents. Double-click the title to rename it, and pick a colour with the swatch beside a selected section's title or in its right-click menu (the default is neutral). Delete removes a selected section together with everything in it, and **Undo** restores them; **Remove section; keep contents** in the right-click menu removes only the frame. Copy, paste and **⌘/Ctrl+D** take a section with its contents. Sections belong to a page, are drawn behind connections and cards, and are included when fitting the view; zoomed out, their titles stay readable above the board, and where titles would overlap, the selected and larger sections keep theirs. Generated images can land inside a section and then belong to it. Sections sync on team boards and undo like other edits.
- Collapse an individual text or image node with its collapse control; the compact square keeps its connections. Its expand control appears on hover or keyboard focus. The state is saved with the board.
- **Auto-align selected nodes** in the bottom toolbar works only on a selection (select two or more nodes or a group first); everything else, including drawings, stickies and stamps, stays where it is, and the aligned nodes keep their top-left corner. It places generations from left to right and orders each column oldest first, centering parents against their children where that order permits. Undated legacy nodes retain their array order before dated nodes; groups use their oldest member and retain internal offsets. It accounts for image sizes and separates overlapping cards. Fold groups first for a compact layout. **Undo** restores your previous positions. Alignment runs only when you press the button.
- Hover over a button for a short explanation. Keyboard focus shows the same hint, and disabled controls explain what they need. Hints stay readable at every canvas zoom.
- Select one image and press **⌘C / Ctrl+C** to copy the image for pasting into other apps. Press **⌘ShiftC / Ctrl+Shift+C** to copy selected node, group or section IDs as text for an agent; you can also find these commands in the node's right-click menu. Select text nodes or multiple nodes and use **⌘/Ctrl+C**, then **⌘/Ctrl+V**, to copy them at the pointer with their internal connections. **⌘/Ctrl+D** duplicates selected nodes with a small offset, keeping incoming parent connections and connections between the copies. Outgoing connections to other nodes stay on the originals. Copies receive a fresh creation time. Copy/paste inside a prompt edits text normally. Clipboard node references work within the same app installation, including across boards.
- **⌘Z / ⌘ShiftZ** undo/redo canvas edits. Delete removes selected nodes/connections. Removed assets remain on disk.
- Double-click an image to inspect it, download the original, and review its saved prompt and input image thumbnails.
- Every run appends results. Editing a prompt never changes the historical snapshot of an earlier run.

For a source-run browser app, boards save automatically to `data/workspace.json`; image originals are in `data/assets/`. The first launch after upgrading an earlier source-run installation imports `data/canvas.json` unchanged into **My concepts**, retaining all nodes, connections, runs, and viewport. The old file remains as a migration backup; subsequent edits go to `workspace.json`. Use one browser tab per board.

The desktop preview uses `~/Library/Application Support/Concept Graph` on macOS or `%LOCALAPPDATA%\Concept Graph\data` on Windows by default. Change the folder via **Concept Graph → Storage Location…** on macOS or **Storage → Change Storage Folder…** on Windows; the app copies and verifies the data and retains the original folder. Earlier browser installations do not automatically migrate to desktop: use board export/import or the data-directory guidance in [desktop-preview.md](desktop-preview.md). In either mode, back up the entire data folder. Files and references are stored locally; connected prompts and images are sent to OpenAI when you run a prompt.

On desktop, **Connect MCP** in the top bar copies a setup message for a local Codex or Claude Code agent. Keep Concept Graph open. The connected agent can read and modify boards and images and start generation; see the [MCP guide](mcp.md).

## Portable boards

Use **Export** and **Import** under the board picker. Export saves current edits before downloading one `.conceptgraph` file. Import saves the current board, then opens a new board named `… (imported)`; repeat imports get distinct names and IDs. Existing boards and original image files are retained.

The archive is a standard ZIP with UTF-8 `board.json` and an `assets/` directory. The manifest stores `format: "concept-graph-board"`, the format version, the board name/creation time, its full graph and history, and an image inventory containing byte sizes and SHA-256 checksums. Boards containing custom-node settings use version 2, which older app versions cannot import; other boards use version 1. Boards with pages use version 5; older archives open with all nodes on the first page. Local board storage that contains pages is likewise marked so older app versions refuse to open it instead of discarding page membership. Images keep their original bytes and include saved run inputs and custom-node references, even when no longer visible on the canvas. Login credentials and unrelated files are not read into exports. The archive can be inspected by renaming a copy to `.zip`.

On import, image filenames are regenerated and all node/history references are updated, preventing collisions with existing images. Incomplete imported runs become cancelled history entries; they never resume or consume allowance automatically. Export during generation captures the board as it exists at that moment and leaves the original generation running.

Limits: 512 MB archive/expanded data, 30 MB per image, 32 MB manifest, 4 MB editable graph, and 5,000 ZIP entries/history runs. Invalid files, unsupported versions, missing images, checksum mismatches, unsafe paths, links, and oversize entries are rejected. Uploads are staged and validated before a new board is added; imports never replace existing boards.

## Development

```sh
npm ci
npm run build
npm test
npm start
```

React Flow provides the canvas. A local Node server stores assets and runs `codex app-server --stdio`. No cloud hosting, external database, or API key is needed. The Codex app-server interface is experimental; updates may require adapter changes.

Set `CODEX_BIN` to the Codex executable if it is not on PATH. `PORT` defaults to 4317, and `CONCEPT_GRAPH_DATA` can select another data folder. The server listens only on 127.0.0.1 and rejects external Host/Origin headers.

Limits: one active generation across all boards, 10 connected image inputs per run, 30 MB per image. Run history survives restarts; interrupted jobs are marked failed rather than silently repeated. Undo history lasts until you leave the board or reload. Boards can be renamed; board deletion is intentionally not included. Generated images do not join an existing group automatically.

For isolated development, set `CONCEPT_GRAPH_DATA` to a separate folder. The server integration test uses a deterministic fake Codex process and never sends requests to OpenAI. To roll back an upgrade, stop the server and restore the matching application and data backup together; retain the newer data folder separately so post-upgrade work is not lost.
